# Native blur lifecycle

The accepted configuration uses Qt `FastBlur` radius 30, a 512×512 capture at logical position (1408, 96), and one explicit texture containing all nine rounded button masks. The masks stay fixed during selection. The web overlay's opaque selected fill covers the blur beneath it, avoiding the timing gap between the web and native surfaces. Main-grid selection changes keep the effect visible; submenus, wallpaper and hidden UI hide it.

The exact source allowlist is `com.webos.app.home`, `com.gathin.tvhome`, `youtube.leanback.v4`, `com.apple.applemusic` and `netflix`. Netflix has exercised the installed coordinator's takeover, rendering telemetry and cleanup; the final manual playback test stayed open but showed no visible blur according to the user. A matching ID alone is insufficient: the original fullscreen item must remain current, have positive dimensions, belong to the same QQuickWindow and neither contain the effect nor be contained by it. App switches invalidate the source. Acceptance of an app's UI is not a claim about protected or separate video planes.

## Launch and reopen contract

Each opening gets a fresh native object and a fresh 64-character hexadecimal token. The launch properties remain `blurToken`, `blurPort: 48740` and `blurSessionDeadline`. The absolute deadline must be in the future and no more than ten minutes away. A stable QML URL may load fresh instances, but an already configured instance rejects another launch and exits using its original session token.

Keep Host.qml and its sibling Backdrop.qml immutable while an instance is alive. Updating the content behind a stable URL is a deployment concern separate from reopening: QML component caching can retain compiled code. Stop and verify the previous host before changing files, and verify the newly loaded version during deployment; use a versioned immutable directory when the runtime provides one.

Normal reopening must serialize behind the previous worker's completed cleanup and native `destroyed` event. The coordinator queues a closing-phase reopen behind the lifecycle lock and checks the predecessor's cleanup before launching or treating a cancelled queued request as safely closed. `systemUIManager/getForegroundAppInfo` omits containers already in the `closing` state. That API's absence check does not independently prove destruction because this implementation deliberately retains its native container in that state while the web overlay owns focus. After a controller crash, the runtime applies a 20-second quarantine for independent lease/timeout cleanup; it does not relaunch based only on foreground absence.

## Bounds and teardown

- Startup waits at most eight seconds for a valid source and web takeover. The web-focus wait shares this absolute ceiling; the earlier separate five-second cutoff was removed without extending any lease.
- The host keeps one long poll in flight, aborting it after 2.5 seconds. The controller normally responds within 900 ms.
- Fresh controller states renew a short lease; duplicate revisions do not. After takeover the host caps each accepted lease at four seconds, checked every 250 ms. The controller normally grants 3.5 seconds.
- The hard session deadline remains independent of incoming heartbeats.
- The native container's first close is retained only when the current overlay is the owned web Control Centre and the fullscreen source is still the original item. Other closes, source loss, hidden host, invalid state or lost web ownership end the session.
- Teardown stops timers, aborts the poll and pending telemetry, releases all source references, clears `keepWindowOnAppSwitch`, sets the close delay to zero and invokes `windowExit`. While already closing, LG's container directly shuts down its close timer.

The explicit mask texture uses `hideSource: true`; its white geometry is not intended to paint directly. Retained scene/effect references survive main-grid hiding to avoid navigation-time allocation changes, but `active=false` or invalid source identity clears every reference. Live scene capture and final effect visibility remain gated by main-grid rendering.

## Blur strength and checks

Qt FastBlur's radius is not CSS Gaussian sigma. The TV's implementation combines downsampled images with bilinear filtering. Radius 30 blends the 256, 128, 64, 32 and 16 pixel levels of the 512 pixel crop; it is not a single Gaussian convolution. The user accepted native radius 30 over Apple Music and launcher CSS `blur(8px)`. Launcher 12px looked close but felt slightly laggier; the accepted 8px setting still had a minor frame drop according to the user. These are visual and responsiveness observations, not equivalent units or measured frame rates.

The crop leaves approximately 40/32/46/54 logical pixels around the inset masks (left/top/right/bottom). `transparentBorder: false` clamps its edges. These margins do not establish an exact filter support bound; stronger settings need visual checks near the capture edges.

The offline native-host checks exercise the actual QML JavaScript methods and selected binding expressions with fake timers, requests and Qt items. They cover source guards, all-nine mask continuity, short leases, stale callbacks, malformed responses, fresh-instance reopening and source-reference teardown. They do not compile QML or measure GPU behavior. The controlled TV trials established native rendering and cleanup, including an independent destruction witness after a killed controller. Earlier saved captures also contained intermittent short pixel-corruption runs; do not infer artifact-free rendering, FPS or complete GPU-memory reclamation from successful lifecycle checks alone.
